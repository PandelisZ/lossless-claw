# PostgreSQL adoption qualification

This extends [native engine results](NATIVE-RESULTS.md); historical timing and source artifacts remain unchanged. SQLite is still the default. No npm release, production DDL, migration or deployment was performed.

## Local synthetic qualification

`mise exec -- node scripts/postgres/run-local.mjs --operations-only --checks-only` runs real PostgreSQL 18 and PgBouncer transaction pooling in uniquely owned disposable containers. The operations suite imports the seed-20261104 fixture (7200 messages, two organizations, three agents each, six conversations per agent, 200 messages per conversation). The immutable fork fixture SHA256 is `597e3a64ffcd3c1121c34323f49fe865b9a2a7708897b76027d1e122f0e35ac0`. Payloads are private synthetic derivatives, including a payload over 256 KiB; original fixture exports are not modified.

Each of the six agent stores imports 1200 messages, runs native engine assembly, appends one message, and backs up/restores 1201 messages plus graph, auxiliary state and payload metadata. Organization SQL privileges are distinct; mapped agents within one organization use trusted native actor routing and separate schemas. Tests cover import interruption/replay, changed payload rejection before import completion, incomplete-store startup rejection, unknown tables/ambiguous authority/cross-agent edges, grant ownership, symlink and ancestor-swap rejection, exact payload bytes, and allocated-but-deleted ID high-water preservation. All native cursor/receipt/pending/focus/maintenance tables are live adapter APIs, not preservation-only auxiliary JSON.

The engine suite includes same-receipt concurrent replay, stale-revision fencing, serialized-tail bounds, actual compaction/summary DAG resolution and all agent/organization boundaries. Direct PostgreSQL runs 21 engine tests plus four operational tests. PgBouncer runs 20 engine tests with one administrative ACL test skipped; a real limited-role two-agent gateway runs through both direct and pooled connections. The parity-only probe compares the complete assembler and complete engine to SQLite for normal, token-budget and prompt/structured cases, with a 200-message/34-summary expanded DAG. Restart verification uses a fresh client through the transaction pooler. These are localhost mechanics and correctness checks, not hosted latency measurements.

The separate `scripts/postgres/failover-local.mjs` probe uses a real local streaming standby and an explicit replay barrier, kills the primary during an uncommitted write, verifies failure and replica-open rejection, then manually promotes and explicitly reconnects. Committed native message/graph/receipt state survives with hash `740e12aeb1fa82424827ce7561142ab36d8fc8d0b9f35918826ba458ea91ba2c`; allocation remains monotonic and the promoted primary accepts new writes. This is not automatic/provider HA, arbitrary-lag RPO, or read-replica support.

## Package and adoption boundary

The operator CLI and [adoption guide](../../docs/postgres-operations.md) cover immutable per-agent payload bundles, limited-role provisioning, gated resumable import, read-only doctor, consistent backup and non-overwriting SQLite rollback. Gateway startup requires complete dedicated credentials, verified TLS outside disposable mode, primary/read-your-writes behavior, preprovisioned ready schemas and a bounded pool. No Rails persistence, outbox, durable job, native-history migration or Honcho replacement is added.

Candidate packaging and the Clawder staging lane are qualified separately against a committed source/archive pin. The package retains all Turbopuffer/root/deep import contracts and its existing released identity; nothing is published. Evidence files are added after the immutable candidate run. A named disposable hosted target is still required to qualify PlanetScale role/catalog compatibility, real network latency, hosted-image installation and provider failover. Neither local restart nor manual promotion proves those behaviors.

The existing SQLite suite ran 143 files: 140 passed, two skipped, one failed only because its exact binary-map expectation needed the new operator binary. The corrected metadata file then passed all six tests. Combined final coverage is 141 passing files/2176 passing tests and two skipped files/25 skipped tests; no broad repeat was used to obscure the initial failure. The additional bundle/credential suite passes 12 tests and TypeScript checks pass.

A separate real PostgreSQL run repeats all four operations tests on the original shared published-tag fixture (SHA256 `af724fb7cd2504ac3e593b16090d63179bdd0ee25e3617991e25d8be14f2b5cf`). It passes all six imports/engine appends/backups/rollbacks, plus the final column-level unrelated-access rejection. See `evidence/ops-published-source-{tests,cutover}.json`. The earlier comprehensive direct/pooler run is captured in `ops-checks.json`; its source inventory predates only this additional shared privilege predicate and regression.
